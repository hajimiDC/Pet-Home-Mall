# 宠物之家商城 · 数据库设计

> 依据《需求文档》v1.2 的 10.3 领域模型、10.4 ER 图、12.1 数据需求与 9.7 后台新增实体清单实现。
> 运行时 DDL：`server/src/db/schema.sqlite.sql`（SQLite，金额以「分」存 INTEGER）；迁移稿：`sql/schema.mysql.sql`（MySQL 8，金额 DECIMAL(12,2)）。

## 1. 设计约定

| 项 | 约定 |
|---|---|
| 主键 | `id` 自增整数（MySQL 为 BIGINT） |
| 金额 | 运行时以**分**为单位的整数（`INTEGER`），服务层整数运算 → 对外 `toYuan()` 返回元；MySQL 版为 `DECIMAL(12,2)` |
| 时间 | 文本 `YYYY-MM-DD HH:MM:SS`（UTC），便于跨库迁移；MySQL 版为 `DATETIME` |
| 多值字段 | JSON 文本（图片数组、适用门店、券范围、收货快照等） |
| 布尔 | `INTEGER` 0/1 |
| 逻辑删除 | `is_deleted`（仅商品），订单/日志/流水**不删除** |
| 表名 | `orders`、`users` 替代 SQL 保留字 `order`、`user`（其余与 ER 图一致） |
| 只增不改 | `stock_logs`、`operation_logs`（仅建索引，不提供更新/删除入口） |

## 2. 实体分组（57 张表）

### 2.1 会员与交易（C 端主链路）

| 表 | 说明 | 关键字段 / 约束 |
|---|---|---|
| `users` | 会员账号 | `username`、`phone`、`email` 唯一；`password_hash`（BCrypt）；`fail_count` / `locked_until` 防爆破 |
| `addresses` | 收货地址 | `is_default`：每用户至多 1 条默认（服务层保证） |
| `favorites` | 店铺收藏 | `(user_id, shop_id)` 唯一 |
| `carts` / `cart_items` | 购物车 | `(cart_id, sku_id)` 唯一（同 SKU 合并）；`checked` 支持勾选结算 |
| `orders` | 订单 | `order_no` 唯一；`(user_id, idempotency_key)` 唯一实现提交幂等；金额四分项 + `pay_amount`；`status` 见 3.1；`receiver_snapshot` 冗余地址 |
| `order_items` | 订单明细 | 冗余 `product_name` / `price` / `spec_name` / `image`，保证历史可追溯 |
| `payments` | 支付单 | `pay_no` 唯一；`status` 0 待支付 / 1 成功 / 2 失败 / 3 已退款 |
| `logistics` | 物流 | 一订单一条有效记录（公司 + 单号）；`tracking_no` 索引 |

### 2.2 商品、类目与库存

| 表 | 说明 | 关键字段 / 约束 |
|---|---|---|
| `categories` | 类目（最多三级） | `parent_id` 自关联；`(parent_id, name)` 唯一；7 个一级 / 50 个二级 / 263 个三级词条（附录 C） |
| `products` | 商品 | `(shop_id, name)` 唯一；`status` 0 草稿 / 1 待审核 / 2 已上架 / 3 已下架 / 4 审核驳回；`total_stock` / `locked_stock` 冗余便于列表 |
| `skus` | 规格 | 价格与库存落在 SKU；`version` 乐观锁；`locked_stock` 预占 |
| `stock_logs` | 库存流水 | 来源（下单锁定 / 支付扣减 / 取消回滚 / 超时回滚 / 手工调整 / 退货入库 / 出入库 / 盘点）+ 变动前后 + 操作人 + 单号 |
| `stock_orders` / `stock_order_items` | 出入库单 | `stock_order_no` 唯一；已提交不可改，只能反向对冲（`status=2` 作废） |
| `stock_takes` / `stock_take_items` | 盘点单 | `take_no` 唯一；记录账面 / 实盘 / 差异 |

### 2.3 店铺、门店与到店

| 表 | 说明 | 关键字段 / 约束 |
|---|---|---|
| `shops` | 店铺 | `name` 唯一；`score` = 评价平均分 ×10（45 = 4.5）；`name_pending` 名称变更审核；`status` 1 营业 / 0 停用 |
| `stores` | 门店 | 经纬度用于距离计算；`business_hours`；`status` 启停 |
| `store_services` | 到店服务 | `store_price ≤ origin_price`；`booking_slots` JSON + `slot_capacity`；`status` 0 待审核 / 1 通过 / 2 驳回 / 3 下线 |
| `store_service_stores` | 服务-门店关联 | 多对多（BR-SLR-005） |
| `store_bookings` | 预约单 | `booking_no`、`verify_code` 唯一；`status` 1 待到店 / 2 已核销 / 3 已取消 / 4 已过期；到店付款，不进入结算链路 |
| `store_verifications` | 核销记录 | 核销码 / 门店 / 核销人 / 收款金额 / 付款方式 |

### 2.4 营销

| 表 | 说明 | 关键字段 / 约束 |
|---|---|---|
| `activities` / `activity_products` | 商家活动 | `start_at`、`end_at`；`status` 0 待审核 / 1 通过 / 2 驳回 / 3 已结束 / 4 强制下线；`rule_json` 存满减/折扣参数 |
| `coupons` | 券模板 | `shop_id=0` 为平台券；`scope_type` 1 全场 / 2 类目 / 3 商品 / 4 店铺；`stock` / `received` / `limit_per_user` |
| `user_coupons` | 用户券 | `status` 0 未使用 / 1 已使用 / 2 已过期；`expire_at` |
| `group_buys` | 拼团活动 | 成团人数 10~99、有效期 3 天；`status` 0 待审核 / 1 进行中 / 2 已成团 / 3 未成团 / 4 驳回 / 5 下线 |
| `group_teams` / `group_members` | 团与成员 | 团 `expire_at` = 开团 + 3 天；成员 `status` 1 待支付 / 2 已支付 / 3 已退款 |

### 2.5 售后、退款、评价、工单

| 表 | 说明 | 关键字段 / 约束 |
|---|---|---|
| `aftersales` | 售后单 | `aftersale_no` 唯一；`(order_item_id)` 进行中唯一（BR-SLR-018）；`respond_deadline` 48 小时响应时限 |
| `refund_orders` | 退款单 | `refund_no` 唯一；`aftersale_id` 唯一（幂等）；`status` 0 待审核 / 1 退款中 / 2 已退款 / 3 已驳回 |
| `shop_reviews` | 商品评价 | `(order_item_id)` 唯一；`reply` 一次性（不可修改，可删除后重发）；`hidden` 申诉隐藏 |
| `review_appeals` | 评价申诉 | 同一评价处理中唯一（`review_id + status=0`） |
| `work_orders` | 客服工单 | `work_no` 唯一；`replies` JSON 留痕 |
| `notifications` | 站内通知 | 类目停用、审核结果、店铺停用等推送商家 |

### 2.6 后台账号与权限

| 表 | 说明 | 关键字段 / 约束 |
|---|---|---|
| `shop_applies` | 入驻申请 | 主体名称 / 电话唯一；`status` 0 待审核 / 1 通过 / 2 驳回 |
| `admin_users` | 后台账号 | `account` 唯一；`type` seller/admin；`shop_id` 商家数据隔离字段；`must_change_pwd` |
| `roles` / `permissions` / `role_permissions` | RBAC | `role.code`、`permission.code` 唯一；内置角色不可删 |
| `auth_tokens` | 会话令牌 | `token_hash` 唯一；`last_active_at` 支撑后台 30 分钟静置登出 |
| `operation_logs` | 操作日志 | 操作人 / 角色 / 模块 / 动作 / 目标 / 请求摘要 / IP / 时间；只增不改 |
| `reconciliations` | 对账 | `(biz_date, channel)`；锁定后不可改 |

| 表 | 说明 | 关键字段 / 约束 |
|---|---|---|

## 3. 状态机

### 3.1 订单（`orders.status`）

```
待付款(0) ──支付成功──> 待发货(1) ──发货──> 已发货(2) ──确认收货──> 已完成(3)
   │                      │                      │
   ├─取消/超时─> 已取消(4) │                      └─退款完成─> 已退款(5)
   └─拼团支付─> 待成团(6) ──成团──> 待发货(1)（未成团 → 全额退款 → 已退款(5)）
```

### 3.2 售后（`aftersales.status`）

```
待处理(1) ─同意·仅退款─> 商家同意(2) ─退款审核通过─> 已完成(5)
    │      └同意·退货退款─> 待买家寄回(3) ─买家填单─> 已收货待退款(4) ─退款─> 已完成(5)
    ├─驳回(必填原因)─> 已驳回(6)
    └─客服介入─> 客服介入中(7) → 同意/驳回
```

### 3.3 到店预约（`store_bookings.status`）

```
待到店(1) ─核销(幂等)─> 已核销(2)（不可取消）
    ├─开始前 2 小时取消─> 已取消(3)
    └─时段已过─> 已过期(4)
```

## 5. 与需求 ER 图的差异说明（有据可查）

| 差异 | 原因 |
|---|---|
| 表名 `orders` / `users` | `order`、`user` 为 SQL 保留字，物理表名调整，字段语义不变 |
| 新增 `store_verifications` | FR-OPS-041 要求查询核销码、核销门店、核销时间、核销人、收款金额与付款方式；`store_bookings` 仅存最后一次核销结果，不足以支撑记录查询 |
| 新增 `shop_accounts` | Q-016 收款账户校验规则需要加密存储、小额打款验证、T+1 生效等字段 |
| 新增 `auth_tokens` | FR-BE-008 后台 30 分钟静置登出、登出/禁用令牌立即失效需要服务端会话表 |
| 新增 `notifications` | FR-OPS-003 / FR-OPS-017 / FR-SLR-005 要求「向商家推送站内通知」 |
| 新增 `favorites` | API-020 店铺收藏需要持久化 |
| 新增 `footer_links` / `shop_recommends` / `featured_products` | FR-OPS-015 / 020 / 026 的运营配置需要结构化存储 |
| 金额字段为整数「分」 | SQLite 无 decimal；整数分等价于定点数，满足 NFR-CONS-004 且可无损映射 MySQL `DECIMAL(12,2)` |
