# 宠物之家商城 · 接口文档

> 依据《需求文档》v1.2 第 10.5 节（C 端 API-001~047、API-151~154）与第 9.6 节（商家端 API-048~089、API-155~156、平台端 API-090~150）实现。
> 需求清单内的 **156 个接口全部实现**（可用 `node scripts/check-api-coverage.js` 复核）；另补齐 10 类「主流程必需但清单未列」的辅助接口（见第 6 节）。

## 1. 统一约定

### 1.1 基础

| 项 | 约定 |
|---|---|
| Base URL | `http://127.0.0.1:8080`，所有业务接口前缀 `/api` |
| 编码 | UTF-8，`Content-Type: application/json` |
| 认证 | `Authorization: Bearer <token>`（JWT HS256） |
| 时间 | `YYYY-MM-DD HH:MM:SS`（UTC），金额单位「元」，最多两位小数 |
| 分页 | 请求 `page`（默认 1）、`pageSize`（C 端默认/最大 20；后台 10/20/50）；响应 `data = { total, rows }` |
| 幂等 | 下单支持 `idempotencyKey`；支付回调/退款/核销/领券服务端幂等 |

### 1.2 响应体

```json
{ "code": 1, "msg": "success", "data": null }
```

- `code`：`1` 成功、`0` 失败（失败时 `msg` 为可直接展示的中文提示，`details.field` 指出出错字段）。
- 列表：`data = { "total": 128, "rows": [...] }`。
- 分页响应可能附带 `page`、`pageSize`、`pageInfo`（越界回退末页信息）。

### 1.3 HTTP 状态码

| 状态码 | 含义 | 示例 |
|---|---|---|
| 200 | 成功（业务失败也返回 200 + `code:0` 的情况仅限历史兼容；当前实现业务失败仍带 4xx） | — |
| 400 | 参数或业务规则校验失败 | `请选择规格`、`库存不足`、`优惠券不可用，请重新选择` |
| 401 | 未登录 / 令牌过期 / 已登出 / 后台静置超时 | `请先登录`、`登录已过期，请重新登录` |
| 403 | 无权限 / 账号禁用 / 验签失败 | `无权访问该功能（403）`、`回调验签失败` |
| 404 | 资源不存在（越权访问亦返回 404，避免探测） | `订单不存在`、`商品不存在或已下架` |
| 409 | 并发冲突（乐观锁版本不一致） | `库存已被其他操作修改，请刷新后重试` |
| 429 | 限流 | `操作过于频繁，请稍后再试` |
| 500 | 服务器错误（日志含 requestId） | `服务器内部错误` |

### 1.4 鉴权差异

| 前缀 | 令牌类型 | 数据权限 |
|---|---|---|
| `/api/**`（C 端） | 会员令牌 | 按 `user_id` 校验资源归属 |
| `/api/seller/**` | 商家令牌（`admin_users.type='seller'`） | 强制 `shop_id` 隔离，忽略请求传入的 `shop_id` |
| `/api/admin/**` | 平台令牌（`admin_users.type='admin'`） | RBAC 权限码（`menu.*` / `action.*`），无权 403 |
| `/api/payments/notify` | 无令牌 | HMAC-SHA256 验签 |

后台会话：登录后 8 小时有效，且**静置 30 分钟自动登出**；登出、禁用、改密令牌立即失效。

## 2. C 端前台接口（API-001 ~ API-047、API-151 ~ API-154）

### 2.1 认证与会员（API-001 ~ 009）

|---|---|---|

## 5. 关键流程示例

### 5.1 下单 → 支付（金额口径）

```http
POST /api/orders/preview
{ "source": "cart", "userCouponId": 12, "shopCouponId": 13 }

200 OK
{
  "code": 1, "msg": "success",
  "data": {
    "goodsAmount": 98, "freightAmount": 10, "couponAmount": 15,
    "activityAmount": 0, "payAmount": 93,
    "freightRule": { "fee": 10, "threshold": 99, "desc": "默认运费 10 元，满 99 元包邮" },
    "shops": [{ "shopId": 1, "goodsAmount": 98, "freightAmount": 10, "payAmount": 93 }],
    "coupons": { "platform": [...], "shop": [...] },
    "address": { "receiver": "张三", "phoneMask": "138****8888" }
  }
}
```

```http
POST /api/orders
{ "source": "cart", "idempotencyKey": "8f1c...", "userCouponId": 12, "shopCouponId": 13 }

200 OK
{ "code": 1, "data": { "orders": [{ "orderId": 1001, "orderNo": "PO20261018...", "status": 0, "statusName": "待付款", "payAmount": 93, "expireAt": "2026-10-18 12:15:00" }] } }
```

### 5.2 支付回调（验签 + 幂等）

```
sign = HMAC_SHA256(payment_notify_secret, `${payNo}|${status}|${amount}|${timestamp}`)
POST /api/payments/notify
{ "payNo": "PAY...", "status": 1, "amount": "93.00", "timestamp": 1790000000000, "sign": "..." }
→ { "code": 1, "data": { "payNo": "PAY...", "duplicated": false, "orderStatus": 1, "orderStatusName": "待发货" } }
```

### 5.3 售后 → 退款 → 财务审核

1. `POST /api/aftersales`（会员，`orderItemId`、`type=2`、`reason`）
2. `POST /api/seller/aftersales/{id}/handle`（`action=approve` → 待买家寄回）
3. `POST /api/aftersales/{id}/return`（买家填物流）
4. `POST /api/seller/aftersales/{id}/confirm-return`（商家确认收货 → 生成待审核退款单）
5. `POST /api/admin/refunds/{id}/audit`（`approve=true` → 退款完成、售后已完成、库存回滚）

### 5.4 拼团

1. `POST /api/group-buys/{id}/join`（不传 `teamId` 开团；返回拼团订单与团信息）
2. 支付 → 订单状态 `6 待成团`
3. 满员 → 团 `2 已成团`，订单转 `1 待发货`
4. 到期未满员 → 团 `3 未成团`，按实付（含运费）全额退款并回滚库存

### 5.5 到店预约与核销

1. `POST /api/store-bookings` → 预约号 + 核销码（无支付单、不占库存）
2. `POST /api/seller/bookings/{id}/verify`（`paidAmount`、`payMethod=到店付款`）→ 幂等核销并写核销记录

## 7. 限流与安全

| 接口 | 限流 | 说明 |
|---|---|---|
| 注册 / 登录（三端） | 20 次/分钟/IP | 配合锁定策略（NFR-SEC-005） |
| 搜索 | 120 次/分钟 | NFR-SEC-010 |
| 领券 | 10 次/分钟 | 防刷 |
| 下单 | 60 次/分钟 | 配合幂等键 |
| 支付 / 沙箱支付 | 30 次/分钟 | — |
| 上传 | 30 次/分钟 | 大小/类型校验 |

其他安全措施：全量参数化 SQL、JWT 签名校验、支付回调 HMAC 验签、商户数据 `shop_id` 强隔离、手机号/地址脱敏、收款账户 AES-256-GCM 加密、审计日志只增不改。
