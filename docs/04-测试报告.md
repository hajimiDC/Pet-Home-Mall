## 4. 性能实测（NFR-PERF-002 / 003）

采样脚本 `scripts/perf.js`：每接口 100 次，单位 ms（含 HTTP 往返）。

| 接口 | P50 | P95 | P99 | max |
|---|---|---|---|---|
| GET /api/products | 1.1 | 2.3 | 6.7 | 6.7 |
| GET /api/products/:id | 0.7 | 1.2 | 2.3 | 2.3 |
| GET /api/cart | 0.6 | 1.1 | 2.6 | 2.6 |
| POST /api/orders/preview | 0.8 | 1.1 | 2.7 | 2.7 |
| POST /api/orders | 3.4 | 6.2 | 17.8 | 17.8 |
| GET /api/orders | 2.1 | 3.0 | 10.9 | 10.9 |

结论：关键接口 **P95 ≤ 6.2ms、P99 ≤ 17.8ms**，显著优于 NFR-PERF-002（P95 ≤ 500ms、P99 ≤ 1s）。
并发下单：20 并发抢 10 件库存，成功 10 单、库存不为负（见 `test/02`），与 NFR-CONS-001 一致；单进程下 100+ TPS 由同步 SQLite + 条件更新保障（NFR-PERF-003 目标 ≥100 TPS，本地压测订单接口顺序吞吐约 300 次/秒）。

|---|---|---|

| 令牌失效 | 登出、禁用、改密、静置 30 分钟、过期令牌调用 `/auth/me` | ✅ 均 401 |
| 水平越权 | 会员 A 访问会员 B 订单 / 商家 S2 访问 S1 商品订单 | ✅ 404，不泄露存在性 |
| 垂直越权 | 财务访问运营接口、运营访问财务接口 | ✅ 403 |
| 支付回调 | 无签名 / 错误签名 / 正确签名重放 | ✅ 403 / 403 / 仅生效一次 |
| 金额篡改 | 提交订单携带 `payAmount:1` | ✅ 服务端复算 108 |
| 限流 | 注册接口连续调用 | ✅ 429「操作过于频繁」 |
| 敏感信息 | 订单/后台列表手机号、日志内容 | ✅ `138****8888`；日志无密码明文 |
| 账户加密 | 收款账户 `account_no` | ✅ AES-256-GCM 存储、对外掩码 |

## 6. 开发期发现并修复的缺陷（回归记录）

| 编号 | 现象 | 根因 | 修复 |
|---|---|---|---|
| D-01 | 平台 `/api/admin/auth/me` 返回 403 | 无权限码的路由在 RBAC 判断中 `perms.some()` 对空数组返回 false | `core/auth.js`：无 `perm` 时仅要求登录 |
| D-02 | 结算/提现接口启动即报「表不存在」 | `schema.sqlite.sql` 缺少 `settlements / settlement_items / withdrawals` | 补建三表（含 `(shop_id, period)` 唯一索引），移除模块内兜底 DDL |
| D-03 | 5MB 图片上传被 6MB 请求体上限拦截 | `MAX_BODY` 小于 base64 膨胀后的体积 | 提升至 12MB |
| D-04 | 商家无法提现（可提现余额恒为 0） | 结算单缺少「确认/打款」状态流转接口 | 新增补充接口 `POST /api/admin/settlements/{id}/confirm`、`/pay` |
| D-05 | 多店铺订单重试可能重复下单 | 幂等键在多店铺场景加了 `-shopId` 后缀，重试匹配不到 | 幂等查询同时匹配 `idempotencyKey` 与 `idempotencyKey-%` |
| D-06 | 同一周期二次生成结算单会漏掉新增可结算订单 | 生成时若结算单已存在直接跳过 | 改为「待确认」状态下并入新增订单并重算金额 |

## 7. 遗留与说明

| 项 | 说明 |
|---|---|
| 后端无前端页面 | 本项目交付后端；浏览器兼容/分辨率类用例（TC-COMPAT-001）与页头渲染需前端配合验证 |
| 第三方支付/地图为沙箱 | 沙箱回调与 HMAC 验签已实现；真实渠道对接需替换 `payment-service` 的渠道适配层 |
| 导出能力 | 订单明细、库存流水、支付流水、操作日志、财务报表支持 CSV；预约单/结算单/活动效果导出列为后续增强（FR-SLR-026/089 的导出子项） |
| 提现风控细化 | 已实现账户验证、T+1 生效字段、小额打款、次数限制；「登录密码 + 短信二次确认」需短信服务接入后启用 |
| 批量改价 | 已支持批量上下架；批量改价（FR-SLR-036 的子项）列为后续增强 |
| 单实例部署 | 定时任务与内存限流为单实例实现；多实例部署需替换为分布式锁/延迟消息与集中式限流（已在架构文档注明） |
