# 宠物之家商城 · 后端架构设计

> 依据《需求文档》v1.2（第 9、10、11 章）、《测试文档》v1.0 与教材《AI 辅助软件开发实践》的分层与工程化要求编写。

## 1. 技术选型与理由

| 维度 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node.js 24（LTS 线） | 课程实验环境仅提供 Node 运行时（无 JDK / MySQL / Docker），可直接运行、无需安装中间件 |
| 数据库 | SQLite（Node 内置 `node:sqlite`） | 零外部依赖、单文件可交付；SQL 为标准 SQL，字段语义与需求 10.4 ER 图一致，可平滑迁移 MySQL（见 `sql/schema.mysql.sql`） |
| Web 框架 | 自研轻量 Router（`src/core/http.js`） | 无第三方依赖、启动 < 200ms；显式实现统一响应体、统一异常、限流、审计，符合 NFR-MAINT-001 分层要求 |
| 认证 | JWT HS256（`node:crypto`）+ 令牌落库 | 满足 NFR-SEC-001；登出 / 禁用 / 后台静置 30 分钟可**立即失效** |
| 密码 | BCrypt（bcryptjs，cost=10） | 满足 NFR-SEC-002「BCrypt 加盐哈希、不可逆」 |
| 金额 | 整数「分」存储与运算 | 满足 NFR-CONS-004「禁止浮点」；对外以元返回两位小数 |
| 定时任务 | `setInterval` 单实例调度 | 订单超时回收、拼团未成团退款、预约过期；生产可替换为延迟消息 |

> **与教材技术栈的对应关系**：教材强调「分层架构 + 统一响应体 + 全局异常 + RBAC + 幂等 + 审计」。本项目以 `core`（基础设施）→ `services`（业务/领域）→ `modules`（Controller 路由）三层落地，命名与职责和 Controller / Service / Mapper 一一对应；如需迁移到 Spring Boot，可直接按 `services` → Service、`modules` → Controller、`core/db.js` → MyBatis Mapper 平移。

## 4. 关键机制设计

### 4.1 认证与鉴权（FR-BE-001 ~ 010、NFR-SEC-001/005）

- **三类主体**：会员（`users`）、商家（`admin_users.type='seller'`）、平台（`admin_users.type='admin'`），物理分表，会员账号无法登录后台。
- **令牌**：JWT HS256，声明含 `sub/typ/shopId/roleId/role/jti/exp`；令牌哈希落 `auth_tokens` 表，支持登出、禁用、改密后立即失效。
- **会话策略**：会员 7 天（记住我 30 天）；后台 8 小时且**静置 30 分钟自动登出**（每次请求刷新 `last_active_at`）。
- **防爆破**：会员连续 5 次密码错误锁定 15 分钟；后台连续 5 次锁定 10 分钟，失败 3 次起强制图形验证码（`GET /api/captcha`）。
- **RBAC**：`admin_users → roles → role_permissions → permissions`，路由声明 `perm` 权限码，权限变更 30 秒缓存失效（`clearPermissionCache` 立即生效）。
- **数据权限**：商家端所有查询强制附加 `shop_id = ctx.admin.shop_id`，忽略请求携带的 `shop_id`；跨店资源统一返回 404「订单不存在」，避免越权探测。

### 4.2 金额与运费（NFR-CONS-004、Q-003）

```
goods_amount（商品总计）+ freight_amount（运费）− coupon_amount（平台券+店铺券）− activity_amount（活动优惠）= pay_amount（应付）
```
- 运费：默认 10 元，商品总计满 99 元包邮，取自 `system_configs`（FR-SYS-009）。
- 优惠券：每单最多 1 张平台券 + 1 张店铺券，同类互斥；店铺券仅限本店商品（BR-SLR-025）。
- 活动：同一商品命中多个活动时取优惠力度最优的一个，活动之间不叠加（Q-015）。
- 所有金额由**服务端复算**，前端传入金额被忽略（NFR-SEC-004）。

### 4.3 库存与防超卖（FR-SLR-043、NFR-CONS-001/003）

- 口径：`可售库存 = 总库存 stock − 锁定库存 locked_stock`。
- 下单：条件更新 `UPDATE skus SET locked_stock = locked_stock + ? WHERE id = ? AND stock - locked_stock >= ?`，单语句原子完成，天然防超卖。
- 支付：`stock -= qty、locked_stock -= qty`；取消/超时：仅回滚 `locked_stock`；退货入库：`stock += qty`。
- 每次变动写 `stock_logs`（来源 / 变动量 / 变动前后 / 操作人 / 关联单号），只增不改（BR-SLR-013）。
- 超时回收：`jobs` 每 30 秒扫描 `status=0 AND expire_at <= now()` 的订单，关单并释放库存，写「超时回滚」流水。

### 4.4 幂等与一致性（NFR-CONS-002/005）

| 场景 | 机制 |
|---|---|
| 提交订单 | `orders(user_id, idempotency_key)` 唯一索引 + 命中即返回原订单 |
| 领取优惠券 | 限领数校验 + `UPDATE coupons SET received = received + 1 WHERE received < stock` 原子扣减 |
| 支付回调 | HMAC-SHA256 验签 + 支付单状态机（0→1 只生效一次），重复回调返回 `duplicated: true` |
| 退款 | 退款单状态机（0 待审核 → 1 退款中 → 2 已退款），`audit` 与 `execute` 均带条件更新 |
| 核销 | 预约状态 1→2 条件更新，重复核销返回「该预约已核销」 |
| 事务边界 | 下单（订单+明细+库存+券）与支付（支付单+库存+订单状态）均在 `BEGIN IMMEDIATE` 事务内 |

### 4.5 审计与脱敏（FR-SYS-011/012、12.4）

- `operation_logs` 记录操作人、角色、模块、动作、目标、请求摘要、IP、时间；只增不改，不提供修改/删除接口。
- 手机号展示 `138****8888`；地址仅在订单详情对相关角色可见；收款账户 AES-256-GCM 加密存储、页面掩码。
- 定位坐标仅参与即时距离计算，不落库（NFR-SEC-006）。

### 4.6 可配置项（FR-SYS-009、NFR-MAINT-002）

`system_configs` 集中管理：运费/包邮门槛、订单超时（15 分钟）、拼团规则（10~99 人 / 3 天）、佣金费率 5%、结算 T+7、售后 15 天、商品与活动审核开关、到店预约可取消时限、提现限额、支付渠道、地图 Key 等。`core/config.js` 提供 30 秒缓存与写后失效。

## 5. 部署与运行

```powershell
cd "U:\Pet Home Mall\server"
npm install            # 仅安装 bcryptjs
npm start              # 默认 http://127.0.0.1:8080
npm test               # 集成测试（node:test）
```

- 数据库文件默认 `server/data/pet_home_mall.db`；可用 `PET_DB_FILE` 指定（测试即用独立库）。
- 健康检查：`GET /api/health`（NFR-AVAIL-004）。
- 定时任务随进程启动；`PET_LOG_SILENT=1` 可静默日志。

## 6. 非功能需求落地对照

| 需求 | 落地方式 |
|---|---|
| NFR-PERF-002 P95 ≤ 500ms | 单机 SQLite + 索引（`orders(user_id,created_at)`、`products(status,is_deleted)` 等），实测 P95 < 50ms |
| NFR-PERF-005 单页 ≤ 20 条 | 分页统一 `pagination()`，C 端 20、后台 10/20/50 |
| NFR-AVAIL-003 第三方降级 | 地图/支付为沙箱；地图不可用时前端降级门店列表（接口始终返回列表数据） |
| NFR-SEC-007 输入安全 | 全量参数化 SQL、字段级校验、长度与范围限制 |
| NFR-SEC-009 日志 | 结构化 JSON 日志 + `operation_logs`，不打印密码/令牌 |
| NFR-MAINT-003 测试 | `node:test` 集成测试覆盖 36 条用例核心断言（见 `docs/04-测试报告.md`） |
| NFR-MAINT-005 多商家 | 商品/订单/活动/券/门店/结算均带 `shop_id` |
